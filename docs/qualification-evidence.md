## How to read the index

| Evidence class | Meaning |
| --- | --- |
| SDK-free contract | Exercises project behavior without a native camera SDK; a project-owned mock CTI is not a vendor SDK. |
| Native SDK fixture | Executes real SDK/producer code against Fake, simulated, recorded or controlled inputs, including offline initialization with no camera. |
| Simulated network transport | Exercises actual protocol traffic against a simulator or controlled endpoint, with or without a native SDK. |
| Physical-camera observation | Measures behavior involving an actual camera in a recorded setup. A diagnostic, discovery ACK, source frame and MEL callback are different observations. |
| Production-qualified | Requires explicit acceptance criteria and sufficient signed-off evidence. No indexed record receives this classification. |
| Blocked / not executed | A target qualification could not proceed or was not run; no outcome is assigned to unexecuted behavior. |

**Positive** means the stated narrow check succeeded; **Negative** means an
executed check returned an error, crashed, or did not meet its target;
**Inconclusive** means the experiment ran but did not establish the proposed
effect. **Blocked** identifies a prerequisite that prevented the target check;
**Not executed** identifies an omitted or unauthorized check. An expected
rejection can support a positive contract result; it does not qualify the
rejected operation. IDs are stable, not versions or a ranking. Use the original
record for exact commands and raw measurements. **Not recorded** means the
available record does not establish the field; a branch base, a record's commit,
and the tested tree must not be substituted for one another. A test source or
CTest registration alone is not a record of execution.

**Even a complete hardware capture does not establish valid MEL integration-start
timestamps, UTC/PTP alignment, optical calibration, navigation-to-image
association, complete MEL conformance, production reliability or support for
different firmware/SDK versions.** Aravis positive MEL tests use a test-only
virtual integration-start clock; the production Aravis and Pleora adapters
return invalid timestamps, which the provider rejects. Native time readback or
host interarrival is not an integration-start mapping.

**Safe reproduction:** start with the [SDK-free quick start](../README.md#sdk-free-quick-start).
The native and physical rows point to historical recipes, not permission to run
them. Use only the stated fixture/topology, explicit SDK pins and entitlement,
and serialize tests sharing a listener port. Physical reruns require a dedicated,
owner-authorized setup, exact device selection, exclusive access, bounded time,
approved volatile changes and independent restoration/readback; never run a
historical write or network-tuning recipe on a shared or operational detector.
Private harnesses, logs, packet captures and pixel archives are not published.

## Register transport and navigation

The [internal register/memory service](device-register-transport.md) lends native
operations under the existing device lock. It cannot bound SDK-internal retries,
extend a profile module's ABI, cancel an in-flight SDK call, or declare that a
timed-out write had no effect. A failure after native write entry is uncertain;
lost ACKs, partial packetization and external side effects are not rolled back.
The experimental [controlled transport](controlled-gvcp-transport.md) and
[single-owner authority](gvcp-single-owner.md) are **not** integrated into
production Aravis or Pleora acquisition.

### Installed documentation assessment

Today [CMake](../CMakeLists.txt) installs the full `docs/` tree. Keep that layout
unchanged in this cleanup: it is part of existing packaging behavior. For a
future packaging change, curate the installed consumer guide, capability/status,
configuration, implementation profile and provenance, and retain the full design
histories, validation records and diagnostic stacks at revision-pinned GitHub
URLs. An installed consumer does not need every experiment, and source-relative
links to uninstalled code or tests are not an offline reference. Validate the
curated bundle and its links with an independent installed consumer before
changing the install rule. This is distinct from the already-curated Pages site.
